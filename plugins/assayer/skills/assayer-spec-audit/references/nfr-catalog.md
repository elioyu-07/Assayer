# Spec 非功能性需求目录（NFR Catalog）

> 本文件是功能规约选择 NFR 的默认目录。它定义默认要求和验证证据，不代表仓库已经具备 CI、可观测或合规平台。
> 本目录是 skill 的默认 NFR 来源；项目明确指定的 NFR catalog 优先。来源选择、冲突处理和最终 readiness 以 `references/authority.md` 为准。

## 1. 使用规则

1. 每个 feature 的 `spec.md` 必须列出所有适用 NFR，并标记 `采用 / 不适用 / 豁免`。
2. `不适用` 必须给出可核实理由；`豁免` 必须写明风险、替代控制、到期日和人类批准人。
3. Agent 可以推荐选择，不能批准豁免。
4. 每条“采用”的 NFR 必须映射到验证命令、测试、检查记录或人工验证记录。
5. 具体项目如需更严格目标，可提高标准，不得降低宪法和部门级规范的底线。

## 2. 通用必选

| NFR ID | 适用条件 | 默认要求 | 最低验证证据 | 豁免批准角色 |
|---|---|---|---|---|
| NFR-GEN-001 | 所有功能 | 外部输入均校验类型、格式、长度和业务规则 | 单元/集成测试或契约检查 | 技术负责人 |
| NFR-GEN-002 | 所有功能 | 错误信息对用户可理解，不暴露堆栈或敏感数据 | 异常路径测试/人工走查 | 技术负责人 |
| NFR-GEN-003 | 所有功能 | 每条 FR/规则至少有一个验证证据 | 追溯矩阵 | 不可豁免 |
| NFR-GEN-004 | 所有功能 | 日志不得记录密码、令牌或完整敏感字段 | 日志检查 | 安全负责人 |

| NFR-WRITE-001 | 创建、提交、审批、更新 | 明确重复提交/幂等策略 | 集成测试或人工并发验证 | 技术负责人 |
| NFR-WRITE-002 | 多表写或状态流转 | 明确事务边界与失败回滚 | `*IT.java` 回滚测试 | 技术负责人 |

| NFR-WRITE-004 | 关键业务变更 | 记录操作人、时间、对象、动作和结果 | 审计日志验证 | 合规/安全负责人 |
